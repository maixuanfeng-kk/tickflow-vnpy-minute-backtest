# 分钟组合回测名称、交易回放与浮盈浮亏设计

## 目标

修复“早盘放量组合”分钟回测结果中的三个问题：结果缺少股票名称、点击每日交易时因无效日期导致整页崩溃，以及选股分析的最佳/最差指标不能表达持仓期间风险收益轨迹。

本次只修改当前功能分支，不同步或推送远端。

## 1. 股票名称

分钟回测仍以自选股代码作为股票池。回测服务使用主数据仓库已有的 `get_name_map(symbols)` 一次性取得名称映射，不从本地分钟 Parquet 目录推断名称。

- 每条成交记录返回 `name`。
- 每条 `per_symbol_stats` 返回 `name`。
- 前端第一行显示名称，第二行显示代码。
- 主数据中找不到名称时退回显示代码，不阻断回测。

## 2. 交易日期与回放弹窗

分钟回测成交记录同时返回：

- `entry_date`、`exit_date`：ISO 日期，供排序、每日交易分组和日 K 回放使用。
- `entry_datetime`、`exit_datetime`：精确到分钟的成交时间，保留分钟回测信息。

前端使用统一日期解析函数：优先读取 date 字段，缺失时从 datetime 字段提取日期。解析前校验日期；无效时不调用 `Date.toISOString()`，弹窗显示“缺少有效交易日期”，不让异常上升到路由错误页。

## 3. 持仓期间最高浮盈与最大浮亏

### 单笔交易口径

每次买入成交时初始化：

- `max_floating_gain_pct = 0`
- `max_floating_loss_pct = 0`

对持仓期间存在分钟 K 的每一分钟，使用该分钟最高价和最低价更新：

```text
分钟最高浮动收益率 = (持股数 × 分钟最高价 - 买入总成本) / 买入总成本
分钟最低浮动收益率 = (持股数 × 分钟最低价 - 买入总成本) / 买入总成本
```

其中买入总成本包含买入佣金；浮动收益尚未卖出，因此不预扣卖出佣金和印花税。

- 最高浮盈取持仓期间分钟最高浮动收益率的最大值，并且不低于 0。
- 最大浮亏取持仓期间分钟最低浮动收益率的最小值，并且不高于 0。
- 买入发生在分钟开盘，买入分钟的高低价纳入统计。
- 卖出发生在分钟开盘，卖出分钟之后的高低价不纳入统计。
- 回测结束强制平仓时，最后一个仍处于持仓状态的分钟纳入统计。

实际成交的 `pnl_pct`、`pnl_amount` 仍按现有含买卖费用和滑点的已实现净收益计算，不受上述浮动指标影响。

### 股票汇总口径

对同一股票的所有已完成交易：

- “最高浮盈”取所有交易 `max_floating_gain_pct` 的最大值。
- “最大浮亏”取所有交易 `max_floating_loss_pct` 的最小值。
- 总收益和胜率继续按现有已实现净收益计算。

分钟组合结果继续返回兼容字段 `best`、`worst`，但其值分别对应最高浮盈和最大浮亏；同时在成交记录中返回明确命名的浮动指标字段。前端仅对分钟组合把列名显示为“最高浮盈”“最大浮亏”，其他回测引擎保留原有“最佳”“最差”语义。

颜色统一按数值正负决定，不再按列固定颜色。

## 数据流

1. API 从自选股取得代码并构造分钟回测配置。
2. 分钟回测服务从主仓库取得名称映射。
3. 撮合引擎在持仓生命周期内更新单笔 MFE/MAE。
4. 平仓记录写入标准日期、分钟时间、名称及浮动指标。
5. 服务按股票聚合已实现收益与浮动指标。
6. 前端安全解析日期并按回测引擎显示相应列名。

## 测试

- 引擎测试：买入分钟、持仓分钟、卖出分钟边界下的最高浮盈和最大浮亏。
- 服务测试：名称、标准日期和每股汇总字段完整。
- 前端测试：date 缺失但 datetime 存在时可解析；完全无效日期不会抛出异常。
- 回归验证：分钟组合后端测试、相关前端测试和前端生产构建。

## 非目标

- 不改变入场、出场、T+1、滑点或费用规则。
- 不把浮盈浮亏加入组合资金曲线计算。
- 不修改其他回测引擎的最佳/最差定义。
- 不在本阶段同步、推送或创建 Pull Request。
