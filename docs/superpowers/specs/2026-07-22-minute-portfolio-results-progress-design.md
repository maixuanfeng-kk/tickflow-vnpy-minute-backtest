# 早盘放量组合回测结果与实时进度设计

## 目标

让“早盘放量组合”在回测页面显示完整、口径一致的组合统计与曲线，并让进度条反映真实的数据读取、撮合和统计进度。默认分钟数据目录改为 `F:\quant\data\minute_1min_pytdx`，页面记住用户最后一次填写的目录。

## 问题根因

分钟组合服务当前只返回 `total_trade_count` 和 `end_balance`，但页面读取 `total_return`、`annual_return`、`sharpe`、`sortino`、`max_drawdown`、`mc_maxdd_p50`、`mc_maxdd_p95`、`win_rate`、`n_trades` 和 `final_equity`。同时，服务返回的净值、回撤、基准和单股统计均为空。

分钟组合接口当前只发送 0/1 和 1/1 两个进度事件，因此加载 609 个 Parquet 文件和执行分钟撮合期间，页面只能长期显示 0%。

## 结果口径

### 组合权益

撮合引擎在每个交易日最后一根分钟 K 结束后记录组合权益：

- 现金按实际成交费用扣减后的余额计算。
- 持仓按当日最后可用收盘价估值。
- 回测最后一天仍持有的股票继续按现有规则强制平仓。
- `equity_curve` 保存 `date`、`value` 和 `positions`。
- `drawdown_curve` 使用组合权益相对历史峰值的回撤。

### 交易盈亏

每笔交易补充：

- `pnl_amount`：卖出净收入减去买入总成本。
- `pnl_pct`：`pnl_amount / 买入总成本`。
- `duration`：入场交易日至出场交易日的自然日数，最少为 0。

费用口径继续使用请求中的佣金、印花税和滑点，不改变现有成交规则。

### 统计字段

分钟组合结果必须返回页面既有契约：

- `total_return`：最终权益相对初始资金的收益率。
- `annual_return`：按回测自然日数复利年化。
- `sharpe`：日权益收益率按 252 个交易日年化。
- `sortino`：日权益收益率的下行偏差口径，按 252 个交易日年化。
- `max_drawdown`：组合权益曲线最大回撤。
- `mc_maxdd_p50`、`mc_maxdd_p95`：对净交易收益率固定随机种子重抽样。
- `win_rate`、`n_trades`、`final_equity`。
- 保留兼容字段 `total_trade_count` 和 `end_balance`。

`per_symbol_stats` 按标的返回交易数、累计交易收益、胜率、最佳和最差单笔收益。

### 同期上证

基准继续使用项目现有上证指数日线仓库。能读取时返回 `benchmark_curve`；数据缺失或读取失败时返回空数组，页面保持“—”，不伪造 0% 收益，也不阻断策略回测。

## 实时进度

后端沿用现有 SSE `progress` 事件结构 `day/total/date/equity`，但把 `day/total` 统一映射为 0–1000 的真实工作进度，避免修改前端通用任务协议。

进度分三段：

1. 0–650：读取并规范化自选股 Parquet。按已处理文件数实时更新，文案为“读取分钟数据 236/609”。
2. 650–950：分钟撮合。按已完成交易日数更新，文案为“撮合交易日 12/20”，同时携带当前组合权益。
3. 950–1000：统计、蒙特卡洛、基准和结果整理，完成时发送 1000/1000。

进度事件应节流：文件读取每 5 只或阶段结束发送一次；撮合每个交易日发送一次。SSE 保活继续保留。

## 数据读取

本地 Parquet 提供方接受可选进度回调。日线准备和分钟准备若需要两次扫描，使用统一的总工作量计数，保证百分比只前进不回退。缺失文件计入已处理数量，但不计入有效股票数。

默认目录改为 `F:\quant\data\minute_1min_pytdx`。前端使用现有本地存储对象保存 `minuteDataDir`；旧存储记录缺少该字段时使用新默认值。

## 错误处理

- 目录不存在：接口返回明确的目录错误；页面不得长期显示 0%。
- 所选区间没有分钟 K：返回明确错误。
- 部分股票文件缺失：继续处理其他股票，并在进度文案中反映处理数量。
- 基准数据缺失：仅基准卡片显示“—”。
- 没有成交：收益、回撤、胜率和交易数返回 0，最终权益等于初始资金，曲线仍返回可用日期上的平坦权益。

## 测试与验收

1. 引擎测试验证净交易盈亏、日权益和最大回撤口径。
2. 服务测试验证页面所需统计字段、曲线和单股统计齐全。
3. 本地 Parquet 测试验证读取回调单调推进并包含文件处理数量。
4. API 测试验证 SSE 在完成前发出多个递增进度事件。
5. 前端构建验证目录字段持久化和现有结果页面类型兼容。
6. 使用 `F:\quant\data\minute_1min_pytdx` 与当前 609 只自选股完成一次 UI 端到端回测，确认进度持续前进、结果卡片和曲线有值。

## 非目标

- 不改变早盘放量策略的入场、止损、均线退出、T+1 或成交价格规则。
- 不修改其他 Matrix 或 vn.py 回测的统计和进度协议。
- 不在缺少基准数据时下载或伪造指数行情。
