# 财务数据本地导入设计

## 目标

在“数据”模块提供一个本地财务数据导入入口。用户每次手动填写已经解压的 XBX 财报 CSV 目录，系统在后台导入并展示结果。导入后的数据供未来的股票池策略读取。

本设计不定义、不新增、不修改任何股票池筛选策略，也不变更日 K 数据流程。

## 已确认的产品决策

- 入口位于数据模块，而不是股票池页面。
- 数据源是已解压的本地目录，不接收 ZIP 上传。
- 目录不保存为默认值；每次导入由用户手动填写。
- 导入使用后台任务，前端持续展示进度和最终结果。
- 本地 XBX 原始字段必须完整归档，后续策略再按实际条件提取需要的财务指标。

## 用户流程

1. 用户在“数据”页的“财务数据导入”区块输入已解压目录，例如 `C:\\data\\stock-fin-data-xbx`。
2. 点击“扫描并导入”。前端立即获得任务编号，按钮变为运行中。
3. 页面每秒轮询任务，显示当前阶段、已处理文件数、总文件数和读取行数。
4. 成功后，页面显示导入时间、成功文件数、财报行数、最新报告期、最新公告日及失败文件摘要。
5. 失败时，页面显示失败原因和失败文件摘要；上一份成功发布的财务数据保持可用。

## 页面设计

“数据”页保留现有日 K、Enriched、财务数据等概览卡片。财务数据概览卡片下方新增独立的“财务数据导入”面板，包含：

- 本地目录文本输入框。
- “扫描并导入”按钮。
- 导入状态：未导入、运行中、成功、失败。
- 运行中进度：阶段、已处理文件数、文件总数、读取行数。
- 完成摘要：最后导入时间、成功文件数、财报行数、最新报告期、最新公告日。
- 失败摘要：最多展示有限数量的失败文件和原因，避免大规模错误撑开页面。

空目录、目录不存在、目录中没有 CSV 或已有全局数据任务在运行时，按钮不可执行或在提交后返回明确中文提示。页面不展示策略参数、不生成股票池，也不预设财务筛选条件。

## 后端接口与任务

在数据 API 下增加以下接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/data/financial-import/status` | 读取最近一次导入的清单和已发布财务库摘要。 |
| `POST /api/data/financial-import` | 接收 `{ "source_dir": "..." }`，启动后台导入并返回任务编号。 |

导入任务复用现有 `pipeline_jobs` 的任务记录、进度轮询和全局运行锁。数据同步或其他全局写入任务运行中时，财务导入不会并发启动；财务导入运行中，同样阻止其他全局写入任务启动。这样可避免多个任务同时替换本地 Parquet 文件。

前端复用现有任务查询接口读取任务状态，无需增加第二套轮询协议。数据导入接口只负责启动任务，数据状态接口负责展示已发布的数据摘要。

## 数据处理

现有 `LocalFinancialCsvImporter` 是唯一的 CSV 解析和发布实现：

- 递归扫描输入目录下的 CSV 文件。
- 兼容首行推广文本、UTF-8 和 GBK 编码。
- 校验 `stock_code`、`report_date`、`publish_date`、`statement_format` 等必要字段。
- 原样保留 XBX 财务字段到 `financials/raw_xbx`。
- 生成当前通用的收入和净利润窄表到 `financials/income`，并记录源文件、报告期和公告日。
- 使用暂存目录后原子发布的方式替换成功数据；解析或发布失败时保留旧数据。

导入状态从清单文件和已发布 Parquet 中汇总。最新报告期和最新公告日均基于已发布数据计算，不根据本机时间推断。

后续股票池策略必须以 `publish_date <= as_of_date` 过滤，保证某个月份的股票池不会使用当时尚未披露的财报。本次仅保证未来策略所需的原始数据和时点字段齐备，不实现具体因子。

## 错误处理

- 输入路径不是目录：任务不启动，返回中文校验错误。
- 未发现 CSV：任务不启动，返回中文校验错误。
- 单个 CSV 无法读取或字段不完整：记录失败文件并继续处理其他文件。
- 全量输入没有可发布记录：任务失败，保留上一版数据。
- 后台任务异常：任务状态标记失败，页面展示任务错误与失败摘要。

## 验收与测试

实现阶段应覆盖以下场景：

1. 有效 XBX 目录可启动后台任务并发布财务数据。
2. 目录不存在和空目录返回中文错误且不改动已发布数据。
3. 含首行推广文本、GBK 文件和无效文件的混合目录可完成导入，并记录无效文件。
4. 导入失败后，旧的 `financials/raw_xbx` 与 `financials/income` 仍可读取。
5. 状态接口能正确返回清单统计、最新报告期和最新公告日。
6. 数据页在运行、成功和失败状态下正确显示，并阻止空目录和重复提交。
7. 现有股票池策略和日 K 同步测试保持通过。

## 范围与回滚

本期不支持直接上传 ZIP、目录记忆、财务数据浏览器、策略配置或股票池发布。ZIP 需要由用户先解压后再输入目录。

运行中的导入失败由导入器的暂存发布机制保护旧数据。若已发布的功能需要撤回，按仓库协作规范使用 `git revert <commit>` 回滚代码；不删除用户本地已归档的财务数据。
